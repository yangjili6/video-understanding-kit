# ADR-0015：OCR 与视觉去重解耦——共享只读帧，两条链路独立

- **状态**：**Accepted**（2026-11-10）
- **影响文件**：`pipeline.mjs`（分页/去重/字幕的编排）、`lib/dedup.mjs`（去掉 subText 判据）、`dsh-plugin/index.js`（三态字段）
- **取代**：**ADR-0013 中「画面相同但字幕不同 → 不判重复」这一条**（其余内容继续有效）
- **相关**：ADR-0012（网格去重）、ADR-0014（字幕带投票，已判不适用）

## 背景：一个开关把去重结果改了

昨天我给去重加了「字幕判据」：画面几乎一样、但这一页的字幕和代表页不同时，判定内容在推进，不删。

代码是这样的：

```js
const subNow = String(p.subText || '')
const subRep = String(pages[repIndex].subText || '')
if (subNow !== subRep) → 保留
```

**单独看很合理。** 今天指挥官关掉 OCR 再跑同一个视频，结果：

| | OCR 开 | OCR 关 |
|---|---|---|
| kept | 17 | **8** |
| grouped | 3 | **7** |
| dropped | 2 | **7** |

**同一个视频、同一份帧、同样的视觉配置，删的页数从 2 变成了 7。**

原因：**OCR 关掉后两侧 `subText` 都是空串**，判据永远相等，等于「没有信息」被当成了「信息相同」，静默退回纯画面比对。

**这个差异本身说明：视觉去重被非视觉输入改动过。** 所以「删 2」和「删 7」两个数，**都还不能当结论**——得等解耦之后，用纯画面的结果重新验。

## 纠正（两条）

> **「OCR 开关不应改变视觉去重结果」是架构约束，不等于「删 7 页」已经证明删对了。**

> **OCR 应读取去重前约定的采样帧集，不能只读视觉去重留下的代表帧，否则字幕变化仍会被视觉去重间接丢掉。**

**第二条我原来完全没想到**：如果 OCR 只读代表帧，那被合并掉的帧里的字幕变化就永远消失了——**视觉去重间接决定了 OCR 能看到什么。** 这是耦合的另一种形态，藏得更深。

## 决策

### 一、帧只存一份，两条链路各读各的

```
视频 → 抽帧 → 只读帧清单
                ├─ 视觉去重 → groups → pages
                └─ OCR      → 带时间戳的文字事件

音轨 → ASR → 带时间戳的语音片段

以上结果 → 时间轴关联层 → 最终输出
```

**不做物理复制。** **复制几百张 JPG 对隔离没有帮助，只增加存储和读写成本。**

**三条纪律**：

1. **中间结果分目录写，不覆盖源帧**
2. **OCR 读「去重前的采样帧集」，不读代表帧**
3. **帧目录等所有消费者都结束再清理**——不能视觉链路跑完就删

### 二、逻辑独立 ≠ 物理并发

**手机上同时解码、推理会争内存和算力。**

**先把依赖掰开，再用受限并发实测总耗时和峰值内存。** **如果更慢就串行或错峰——架构不受影响。**

### 三、视觉去重只看视觉

**去重回答的是**：**这些帧是否足够相似，可以共用一个视觉代表？**

**它不回答**：**这些时间点是否出现了不同的信息？**

**后者属于内容组织，属于时间轴融合层。**

**所以**：**`dedup.mjs` 里那段 `subText` 判据删掉。视觉算法和阈值保持现状不动。**

### 四、字幕变化在内容组织层表达

**同一静态画面出现三句字幕时**：

```
视觉上：保留一个代表帧
文字上：保留三个有各自时间范围的事件
```

**如果最终产品需要拆成多张展示卡，那是展示层拆卡，不是重写视觉去重结论。**

### 五、映射由独立关联层维护

**共同契约**：

```text
frame      ：frameId、timestamp、path
visualGroup：groupId、representativeFrameId、memberFrameIds
page       ：pageId、所属 groupId / frameId
ocrEvent   ：eventId、start、end、text、sourceFrameIds
```

**三条关键约束**：

1. **去重是减少代表图，不是抹掉被合并帧的时间记录。** 每个输入帧归到哪一组，要保留下来。
2. **同一视觉组可能在不同时间反复出现，不能直接拿「最早到最晚」当连续覆盖区间。** 应保留成员时间点，或明确的不连续区间列表。
3. **OCR 先形成自己的时间事件，再按时间重叠、来源帧关联到组和页。** 允许一页对应多条文字、一条文字关联多页，也允许文字暂时没有页面承载。

**页数和布局由视觉/排版链路决定，OCR 不决定页数。** 关联层只生成关系，不回写视觉判定。

### 六、OCR 状态必须是三态

```
disabled   —— 开关关着，没跑
failed     —— 跑了但失败
completed  —— 跑完了
```

**只有 `completed` 且没有文字，才是「未检出」。**

**空串不能同时代表「关了」「失败了」「确实没字」——**今天正是被这个坑掉的。

## 最小验收

- **同一视频、同一帧清单、同一视觉配置下，OCR 开／关／失败三种状态，视觉分组、代表帧和视觉页数必须完全一致。**
- **静态画面字幕连续变化**：允许合并视觉代表，文字事件不得随之丢失。
- **同一画面隔一段时间再出现**：不能把中间时段错误归给它。
- **串行与受限并发输出一致**，再比较性能。
- **单独人工核查那 7 页是否确实冗余。**

**先改数据流和依赖关系，再验收删页是否正确。** **不要把「与 OCR 解耦」直接当成「去重准确」。**

## 不改的东西

- **「内容有视觉、文字两个维度」这个概念本身是对的**，不撤
- **视觉去重算法和阈值不动**（pHash + 2×3 局部复核）
- **`screenText` 那条链路不动**（它属于 OCR 侧，不是视觉侧）

## 另一个边界

**「只看画面」仍可能看到字幕像素的变化**——**字幕烧在画面上，遮不遮是个独立问题。**

**当前先移除 OCR 判据，保持视觉算法及阈值不变。** **是否遮罩字幕区域，是另一项独立实验，不要顺手混进这次修改。**
