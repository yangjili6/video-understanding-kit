## 一、完整版（推荐）

**视频理解工具包 dsh-video-kit**　|　个人项目　|　2026.10 – 至今

面向 AI Agent 的长视频理解工具链：把视频转成带时间戳的「网格图集 + 字幕时间线」，让多模态模型逐页读取，解决长视频无法整段输入的约束。

- **设计自适应采样算法**：以「图像槽位」为预算单位，按「时间骨架 → 镜头补缺 → 变化加权」三级分配帧预算。骨架约束全片最大帧间隔，镜头补缺保证每个镜头至少一个代表帧，剩余预算按画面变化强度加权插入。
- **构建可验证的阅读门禁**：记录模型实际打开过的页，不足则拒绝出结论；输出「采样页阅读率」与采样版本指纹，明确区分「采样读完」与「全片无遗漏」。
- **打通端侧多模态链路**：镜头检测、字幕 OCR、语音转写、重复页去重、拼图渲染全部在 Android 手机上以 Node.js 完成，无 Python 依赖、无云端服务。

**技术栈**
- **语言 / 运行时**：Node.js（ESM，纯 JavaScript）；唯一 npm 依赖 `onnxruntime-web`
- **模型**：TransNetV2（`transnetv2.onnx`，镜头边界检测）· PP-OCRv4（`ch_PP-OCRv4_det` + `rec`，DB 文本检测 + CTC 解码，识别硬字幕）· sherpa-onnx + Paraformer（中文语音转写）· 多模态视觉大模型（逐页读网格图）
- **算法**：自适应采样（时间骨架 + 镜头补缺 + 变化加权，自研）· 直方图帧差变化检测（48 bin，中位数归一化 + 25 分位噪声底线）· pHash 两级去重（全图 64×64 灰度初筛，汉明距离 ≤6 进入 2×3 局部 ROI 复核，>10 判为有变化）
- **工程工具**：ffmpeg / ffprobe（抽帧、六格拼图）、ImageMagick（灰度转换）、ONNX Runtime Web（WASM 推理）
- **平台**：Android（arm64），全本地运行

**量化结果**：135 秒视频页数 111 → 20（信息密度不变）；198 秒、35 个镜头的视频实现**镜头覆盖 100%、最大帧间隔 10.4s → 2.0s**；198 秒视频端到端约 5 分钟。

## 技术选型问答（面试用）

**为什么用 ONNX Runtime Web 而不是原生 ORT？**
因为要跑在 Android 的 Node 环境里，没有可用的原生绑定；ORT Web 的 WASM 后端能在纯 JS 运行时里跑，代价是速度，但对 4.5MB 的 PP-OCR 检测模型和 48×27 的 TransNet 输入来说够用。

**PP-OCRv4 怎么用的？**
det 模型出 DB 概率图，阈值 + 连通域得到文本框；rec 模型裁剪后 resize 到高 48，走 CTC 解码。两段都是 ONNX。

**为什么要 pHash 两级去重？**
一级全图 pHash 只能发现"整页几乎一样"，但一页有 6 格，只要有一格变了就不是重复页。所以二级把页切成 2×3 区域再比，任一区域汉明距离超阈值就保留。原则是「不确定就保留」，宁可多留也不误删细微动作。

**变化强度为什么不直接用像素差？**
像素差对镜头运动、光照变化太敏感。用直方图帧差 + 按视频自身中位数归一化 + 25 分位噪声底线，能把"压缩噪声"和"真实场景切换"分开。
