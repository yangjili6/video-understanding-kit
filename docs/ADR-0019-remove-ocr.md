# ADR-0019：删除 OCR，改由 VLM 直读网格 + 落成结构化文本

- 状态：已接受（2026-11-15）
- 取代：ADR-0011（视觉强制执行）里的「硬字幕由 OCR 提供」那部分
- 相关：ADR-0017（画面文字区域追踪，已废弃）、ADR-0018（帧级去重）

## 背景

这个插件原本有两条字幕来源：ASR（语音）和 OCR（画面硬字幕）。OCR 这条线在真实内容上反复失败，而且失败方式比"读不出"更糟——它会读错，错字还被下游当成事实。

实测证据（2026-11 期间，同一套 pipeline、同一份模型）：

| 内容类型 | OCR 输出 | 实际字幕 |
|---|---|---|
| 漫画气泡 | `口养尺（测量附）四彩色卡纸（届色m）` | 完全无关 |
| 游戏 UI（480 宽检测） | 0 个框 | 满屏 UI 文字 |
| 豆包 AI 动画（艺术字） | `略略略浓蛋` | 略略略笨蛋用户 |
| 同上 | `来圳我` | 来抓我呀 |
| 同上 | `天肥鱼` | 大肥鱼 |
| 同上 | `彼我抓到有你好果子吃！` | 被我抓到有你好果子吃！ |
| 梗图（大字） | `核子` | 孩子们 |
| 日语中字（印刷体） | 14 条全对 | 对 |

也就是说：**OCR 只在"印刷体、位置固定、字号足够"时可靠**，而这类内容本来就只是硬字幕的一个子集；一旦换成艺术字、气泡、UI，它就变成噪声源。

成本上也不划算。76 秒视频的完整流程 136 秒，其中 OCR 占 19–39 秒（det 217 帧 × 0.65s 是大头），ASR 占 32 秒。为了一个在多数内容上都不准的结果付这么多时间，不成立。

## 决策

**删除 OCR 整条线**（det + rec + 字幕差分筛帧 + 相关模型与 worker），字幕信息改由 VLM 在 `video_look` 读网格时直接读出，并通过 `video_read_page` 落成结构化文本。

### 为什么这不是"失去文本能力"

最初反对删 OCR 的理由是「OCR 是唯一能产出字符串的通道，有了字符串才能检索」。这个理由经实测被推翻：

**VLM 读图时本来就能把字打成字符串。** 字幕条带是放大的、去重后的字幕图像，VLM 读它比读原帧更准（实测艺术字、日文假名都能读对）。只要读完让它填一份 JSON：

```json
{ "t": 0.82, "endT": 1.32, "text": "为什么大和型战舰" }
```

文本能力就回来了，而且质量比 OCR 高——VLM 会结合画面语境判断字形（`孩子们` 不会被读成 `核子`），OCR 只看像素。

差别只在「自动化」：OCR 不需要模型介入，VLM 读需要一次推理。但对本工具的使用场景（人让 AI 看视频），本来就有 VLM 在场，这次推理是顺带的。

### 字幕条带：替代 OCR 的字幕可视化

删掉 OCR 后，字幕仍然需要在网格里可见。方案是**字幕条带**（`lib/band-strip.mjs`）：

1. 取该页时间段内的画面，按 2fps 裁出字幕所在的那一条
2. 对这条做图像去重（pHash ≤ 10 / SSIM ≥ 0.88），同一句字幕的相邻帧合并成一段
3. 去重后的段按 **6 格/行**排版（超过换行，不设总上限）
4. 拼到网格页底部，与画面组成**一张图**的 `enh-<page>.jpg`

这样做的两个目的：
- **找回被帧级去重删掉的字幕**：网格只剩 6 个时间点，中间字幕变过就丢了；条带把这些状态补回来
- **省 token**：画面和字幕在一张图里，不用传两次

### 字幕带位置：不再依赖 OCR 探测

原来字幕带的坐标来自 16 个探测帧的 det 投票。删掉 det 后改用**图像差分**：

- 抽 16 个探测帧（960 宽灰度）
- 对相邻帧算**逐行差分**（每一行的平均变化量）
- 变化最频繁、位置最固定的连续行区间 = 字幕带

这条判据的依据是：字幕是「位置固定 + 内容高频变化」的区域，而画面里的其他东西要么不动，要么整片一起动。它不需要认识字，只需要看哪里在变。

（实现细节见 `lib/band-probe.mjs`；阈值待实测后固化到本 ADR。）

## 结构化输出：五要素 JSON

VLM 拿到的不再是「图 + 一段散文」，而是「图 + JSON」。JSON 必含：

1. **网格图的时间段与 ID**：`grid.id` / `grid.from` / `grid.to`
2. **每一帧的时间戳与 ID**：`frames[].id` / `frames[].t`
3. **每条字幕的时间戳与 ID**：`bands[].id` / `bands[].t` / `bands[].endT`
4. **网格中帧的数量**：`frameCount`
5. **字幕条带中字幕条的数量**：`bandCount`

另加大条/行/格三层定位：

```json
"bandStrip": {
  "id": "g01-p01-band",
  "rowCount": 2,
  "itemCount": 7,
  "rows": [
    { "id": "g01-p01-band-r01", "index": 1, "itemCount": 6 },
    { "id": "g01-p01-band-r02", "index": 2, "itemCount": 1 }
  ]
},
"bands": [
  { "id": "b01", "rowId": "g01-p01-band-r01", "row": 1, "col": 1, "t": 0.82, "endT": 1.32, "frames": 2 }
]
```

**为什么要行列而不只是一维序号**：一条大条最多 6 格，超过就换行；18 格的大条里「第 7 格」是不明确的，而「第 2 行第 1 格」是唯一的。

## 视频阅读库

VLM 读出的内容要能跨会话用，所以落库（`lib/library.mjs`）：

```
$DSH_HOME/storages/dsh-video-kit/library/
  index.json        ← LRU 顺序（最近访问在前）
  <taskId>/
    video.mp4       ← 原视频副本
    reading.json    ← 字幕文本 + 时间戳（可检索）
    meta.json       ← 每页 summary / visual
```

**最多保留 3 条**，超出按 LRU 整目录删除（含视频副本，避免磁盘膨胀）。3 条是手机存储与"最近看过什么"之间的折中——真要长期归档应该导出到别处，不该让工具自己无限吃盘。

对应工具：
- `video_read_page`：VLM 读完一页，提交该页字幕（内容+时间戳）与总结
- `video_library`：查看库内最近 3 条（或指定某条的完整阅读结果）

## 删除清单

| 文件 | 处置 |
|---|---|

| `lib/ocr-det-worker.mjs` | 删除（det 并行 worker） |
| `lib/subtitle-diff.mjs` | 删除（差分筛帧，为 OCR 服务） |

| `pipeline.mjs` 的 `--subs` / `harvestSubs` | 删除 |
| `index.js` 的 `subsCount` / `video_look.subs` | 删除（改由 `page.bands` + 阅读库提供） |

## 影响

**变快的部分**：
- 少 19–39 秒 OCR（76 秒视频的 136 秒总耗时里）
- 少 4.5 MB 模型常驻内存
- 少一套 det/rec worker 的并发管理

**变慢/变复杂的部分**：
- 每个视频多一次 VLM 逐页读图（这本就是必要动作，只是现在要它同时输出字幕 JSON）
- 字幕时间精度从「OCR 的帧级」降到「字幕条带的 0.5 秒」——对"这句话在第几秒"够用，对逐帧对齐不够

**不会失去的**：
- 字幕文本（VLM 读出并入库）
- 时间戳（从字幕条带帧推）
- 跨会话检索（`video_library` + `reading.json`）

## 附：一个被证伪的方向 —— 用图像统计判断「这条带有不有字」

删掉 OCR 之后，「这条字幕带里到底有没有字」成了一个需要单独回答的问题：没有硬字幕的视频也会被切出条带（那只是画面的一部分），于是 `bandCount > 0` 却不含任何文字。下游拿到会误以为「有字幕但读不出」。

我试过两个纯图像指标，都失败了：

| 指标 | 定义 | 有字幕（大和号） | 无字幕（DeepSeek） | 有字幕（大肥鱼） |
|---|---|---|---|---|
| `edgeDensity` | 全图梯度超过 22 的像素占比 | 0.4535 | 0.3499 | — |
| `strongContrast` | 与 3px 外邻居亮度差 > 90 的像素占比 | 0.2011 | 0.1664 | 0.2342 |

两档差距只有 0.03–0.10，落在同一分布里，**定不出阈值**。

**原因不是阈值没调好，而是信息不足**：条带是「画面 + 可能的字幕」的混合，画面里的沙发纹理、衣褶、窗框、头发高光，在边缘密度和高对比这两个维度上与白字黑边的笔画完全重叠。想靠像素统计把两者分开，等于要求统计量具备字形识别能力。

**结论**：这两个字段保留为参考值（写进 `bandStrip`），但**不做判定**。真正回答「有没有字幕」的是读图者提交的 `subtitles` 数组——空数组就是没有。

这条记录的用途是：以后不要再花时间去调这两个阈值。

## 附：为什么不在 OCR 上继续调

试过的方向与结果：

| 方向 | 结果 |
|---|---|
| 提高检测分辨率（480 → 720 → 960） | 720 能检出 9 个框，但**认字仍然错**（模型域不匹配） |
| 分级扫描（大字 320 + 小字 480） | 游戏 UI 这类全是小字的视频，L1 什么都检不出，等于白付一倍成本 |
| 画面文字区域追踪（ADR-0017） | 位置追踪对了，但**认出的字还是错的**——问题在识别不在定位 |
| 只保留字幕线（本 ADR 之前的状态） | 字幕线在印刷体上确实准，但**覆盖不到艺术字/气泡/UI**，而这恰恰是用户实际会看的视频类型 |

结论：**瓶颈在"模型能不能认识这种字形"，不在"流程能不能定位到它"**。换流程救不了，换模型（更大的 OCR）在手机上跑不动。所以交给本来就要看图的 VLM。
