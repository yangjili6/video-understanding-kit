# ADR-0001：ASR 分段与结果过滤

- **状态**：Accepted（2026-10-30，v0.1.5 落地）
- **影响文件**：`asr.mjs`（仓库根与 `dsh-plugin/lib/videokit/` 两份副本）
- **相关实验**：[2026-10-30 实验报告](EXPERIMENT-2026-10-30-asr-ocr.md)

## 背景

ASR 链路的初版是这样跑的：

1. `ffmpeg silencedetect=noise=-30dB:d=0.4` 找出静音区间；
2. 静音区间的**补集**当作语音段；
3. 每个语音段整段送进 paraformer，一次 `decode` 出文本；
4. 识别出非空文本就收为一条 cue。

在一个 30 秒的真人实拍视频上暴露了问题：只出 4 条，其中 2 条是「啊啊」「你用户」这种碎片，中间 19 秒完全空白。

拆开看，两类问题混在一起：

- **A. 分段问题**：静音检测把哪些区间算作「有人在说话」。
- **B. 解码问题**：给 paraformer 的音频有多长。

分开测之后（见实验报告 §4、§5）发现 B 才是大头：同一段音频里，**段越长识别越差**，而且长段还会让时间戳粒度粗到没法用。

## 决策

### D1. 超长语音段等分切碎，上限 25 秒

`detectSpeechSegments()` 之后加 `splitLongSegs()`：长度超过 `ASR_MAX_SEG`（默认 25s）的段，按 `ceil(len / 25)` 等分成 n 段。

理由：paraformer 是**整段一次性解码**的离线模型，没有内部流式对齐；一段喂进 80 秒以上，文本开始出现明显错字（实测「动筷子」→「冻筷子」、「滑管」、「这知了酱汁了」），而且整段只出一条 cue，时间戳等于没有。

代价：长片子的 cue 数量变多（210s 的片子从 8 条变成 13 条），但每条的定位精度提高到 ~20 秒级，总耗时反而下降（120s → 87.4s，见实验 §6）。

### D2. 纯语气片段直接丢弃

新增 `isNoiseOnly(text)`：去掉标点后长度 ≤ 3 且全部由语气字（啊哦嗯呃唉哎哈嘿呀哇喔噢欸呢呐啦哟）组成的结果，判为底噪误识别，不入 cue。

理由：背景音乐和环境音常被硬识别成「啊」「啊啊」「嗯」，这类结果不携带任何信息，却会占用一条候选、干扰后续阅读。实测实拍片少 1 条噪音（4 → 3），动画片零误伤。

风险控制：只过滤**纯语气字**，不做泛化的「短结果丢弃」——「好像」这种两个字但有语义的结果要保留（动画片里确实出现过）。

### D3. 静音阈值保持默认 30dB，但开放环境变量

`ASR_SILENCE_DB`（默认 30）、`ASR_MIN_SILENCE`（默认 0.4）可调，但**默认值保持不动**。

理由（这是本次最重要的一条反直觉结论）：放宽到 35dB 确实能在**实拍片**上多捞 2 条（3 → 5），但同一设置在**动画片**上会让静音段合并成长段，配合 D1 之前的状态反而退步（13 → 9 条）。两种素材的音频特性相反，不存在一个折中值同时最优。

因此：默认值按「人声清晰、配音为主」的常见情形优化（30dB），实拍素材由使用者按需覆盖。

## 拒绝的备选

### R1. 固定窗口切分（每 8 秒一段、重叠 1 秒）

测过（实验 §4）：出 5 条，其中「旅行」是明确的误识别，且会切碎正常句子边界。比静音切分更"均匀"，但完全无视音频内容，对长片的浪费也更大。

**拒绝**：不如「静音切分 + 长段等分」组合。

### R2. 整段不切分

30 秒样本整段识别出 1 条：「嗯诱惑我我只是在看金鱼的学习资料啦」。**文本本身是对的**，说明长上下文确实有帮助——但：

- 时间戳范围等于全片，失去定位价值；
- 210 秒的片子整段喂进去直接跑偏（实验 §5，-35dB 那组）。

**拒绝**：拿时间戳换准确率不划算。

### R3. 上降噪模型（gtcrn）

`sherpa-onnx` 自带 `createOfflineSpeechDenoiser`，下载 `gtcrn_simple.onnx`（523KB）实测：

| | 整段识别结果 |
|---|---|
| 原始 | 嗯诱惑我我只是在看金鱼的学习资料啦 |
| 降噪后 | 啊啊诱惑我我只是在看金鱼的学习资料啦 |

5 秒分段对比里，降噪版把「啊」变成「好笨」、把「旅行」变成「是」——**没有变好，只是换了一种错法**。

**拒绝**：这段素材的问题不是信噪比低，而是人声本身太轻太短，模型在信息不足时只能瞎猜，降噪不增加信息量。若将来遇到「人声清晰但有持续背景噪音」的素材，可以重新评估。

## 后果

**好的**：

- 动画类素材识别条数与准确率明显提升（8 条/120s → 13 条/87.4s）；
- 时间戳粒度从「整片一条」变成 ~20 秒级，`video_frame` 定位才有意义；
- 实拍素材的纯噪音条目被自动清掉。

**坏的 / 要留意的**：

- `splitLongSegs` 里踩到过一个 `Number(null) === 0` 的坑：最后一段用 `end: null` 表示「到结尾」，最初的 `Number.isFinite(Number(s.end))` 判定把它算成 0 秒，导致 124 秒的段整段跳过切分。已改为显式判空，回归用例见实验 §6。
- 25s 是经验值，没有做参数扫描。段落更碎可能进一步提高准确率，但 cue 数量会膨胀，需要额外的合并策略，暂不做。
- 语气词黑名单是硬编码的，方言/口音素材可能需要扩充。
