# 实验 2026-11-03：网格 vs 局部连续帧 —— 动作判断对照

- **目的**：验证「网格图丢细节」是不是动作判断不准的主要瓶颈
- **状态**：单组单样本，**结论力度有限**
- **素材**：BV1A6HC6HEFy「捏捏小猫gemini」，16s，720×1280，取 0–10 秒
- **对照组**：
  - **A**：现有网格（6×3，18 帧，每格缩到 320 宽）
  - **B**：局部连续裁剪（固定窗口 crop=570:500:150:450，每格 400 宽，3×2 六帧）+ 全景

## 记录表（霁璃定的四项）

| 记录项 | A 组（网格） | B 组（局部连续） |
|---|---|---|
| 接触位置是否可见 | **部分可见**——能看出手在脸颊附近，手指形状糊 | **清晰可见**——拇指按压、脸颊变形的接触点都在 |
| 关键过程是否采到 | **采到了**——捏脸动作在多个帧里 | **采到了**，且连续帧之间表情过渡连贯 |
| 动作判断是否正确 | **「手在捏/碰脸」**——能判断到「接触」级别 | **「手指捏脸颊」**——同样正确，且能看出是拇指 |
| 是否选择「无法区分」 | **否** | **否** |

## 结论

**「网格丢细节」在这组样本里不是主要瓶颈。**

A 组虽然每格只有 320 宽，但「手接触脸」这个关键信息**仍然可读**——手指方向、接触位置、猫娘张嘴的表情都在。B 组更清晰（能看到拇指按压和脸颊变形），但**两边得出的动作判断一致**。

这与「局部放大能直接解决根因」的假设不符。至少在「捏脸 vs 摸头」这类**接触型动作**上，网格的分辨率是够的。

## 边界（不能推广）

- **单组单样本**：一部 16 秒动画、一个动作。不能推出「所有动作都不需要局部放大」。
- **动作类型偏简单**：捏脸是「手+脸」的空间关系，网格能保留。**手指形状区分**（捏 vs 掌压）、**快速动作**（挥手、拍打）可能在网格里就糊了——这两种没测。
- **B 组裁剪窗口是我手选的**：真实管线里需要自动定位手/脸，这一步的失败率没测。
- **没有真人素材**：动画的线条清晰度高，真人视频（尤其是运动模糊、暗光）可能结论不同。

## 下一步（如果要继续）

1. 换**复杂动作**再测：挥手、转身、快速拍打（网格可能真的糊）
2. 测**自动裁人**的准确率（现在人工选窗口，不具代表性）
3. 拿**真人视频**测一组
4. 如果复杂动作也扛得住 → 局部放大的优先级可以降，把精力放回「时间戳/阅读顺序」这种更便宜的东西上

## 素材与命令

```bash
# 抽帧
ffmpeg -ss 0 -t 10 -i BV1A6HC6HEFy.mp4 -vf fps=2 -q:v 2 frames/f-%02d.jpg

# A：网格
ffmpeg -i frames/f-%02d.jpg -vf "scale=320:-1,tile=6x3:padding=4" -frames:v 1 A-grid.jpg

# B：局部连续（固定窗口）
for i in 03 04 05 06 07 08; do
  ffmpeg -i frames/f-$i.jpg -vf "crop=570:500:150:450,scale=400:-1" crop/c-$i.jpg
done
ffmpeg -i crop/c-%02d.jpg -vf "tile=3x2:padding=6" -frames:v 1 B-crop-grid.jpg
```

# 第二组：复杂动作（真人羽毛球）

- **素材**：BV1Xthz6LEu1「太极丹的暴力美学」，35s，720×720，取前 17.5 秒
- **A**：网格 6×3（18 帧，每格 320 宽）
- **B**：局部连续（固定窗口 crop=360:400:160:280，6 帧，每格 400 宽）
- **目的**：验证「快速运动」是否会让网格失效

## 记录表

| 记录项 | A 组（网格） | B 组（局部连续） |
|---|---|---|
| 接触/动作位置是否可见 | 可见——能看出是羽毛球比赛、两名选手位置 | 更清楚——球拍角度、站位、腿部姿势都放大了 |
| **关键过程是否采到** | **❌ 没采到**——18 帧里没有挥拍/扣杀瞬间 | **❌ 同样没采到**——我挑的 6 帧都是走位 |
| 动作判断是否正确 | **「选手在移动/准备击球」**——只能到这一级 | 同样只能到这一级 |
| 是否选择「无法区分」 | **是**——分不清是扣杀、拉吊还是接发球 | **是** |

## 关键发现：这组暴露的是**采样问题**，不是分辨率问题

两组都没拍到挥拍瞬间。原因不在网格分辨率，而在：

1. **2fps 采样太稀**——羽毛球扣杀在 0.2~0.4 秒内完成，2fps 很可能整段错过
2. **前 17.5 秒不一定包含精彩回合**——我只按「看一半」截取，没先定位动作密集段

**换句话说**：把画面放大十倍也没用，因为**关键的那一帧根本没进帧序列**。

这印证了霁璃的提醒：「没奏效也可能是采样跳过关键时刻」，而不是「素材问题」或「细节不够」。

## 与第一组的对比

| | 第一组（捏脸） | 第二组（羽毛球） |
|---|---|---|
| 动作速度 | 慢（持续按压） | **快（挥拍瞬间）** |
| 关键帧是否采到 | ✅ 采到了 | ❌ 没采到 |
| 网格是否够用 | ✅ 够（能判断到「捏脸」） | ⚠️ 无法判断——**但这是采样的锅** |

## 下一步（如果有第三组）

1. **先定位动作密集区间再抽帧**（帧差找峰值 → 在峰值附近补抽），验证「补抽关键帧」能不能救回第二组
2. 提高局部采样率到 5~10fps，看挥拍是否出现
3. 只有「关键帧采到、但放大后仍看不清」才归因于分辨率

**在没有第三组之前，不能得出「网格分辨率不够」的结论。**

# 第三组：帧差定位 + 峰值附近补抽

- **目的**：验证「补抽关键帧」能不能救回第二组漏掉的快速动作
- **方法**：全片 2fps 帧差找峰值 → 在两个峰值附近用 10fps 补抽
- **素材**：同第二组（BV1Xthz6LEu1，35s）

## 峰值定位

```
t=10.0s  分数 89.1   ← 最高
t=9.5s   分数 86.0
t=28.0s  分数 86.0
t=28.5s  分数 79.8
t=19.0s  分数 47.5
```

## 补抽结果

| 区间 | 2fps 帧数 | 10fps 帧数 | 看到了什么 |
|---|---|---|---|
| t=9.5~10.6s | 2 | **11** | 前 1 帧正常、**中间 2~3 帧严重模糊**（快速移动/转场）、后面恢复 |
| t=27.8~28.9s | 2 | **11** | 前 3 帧正常、**第 4~5 帧模糊**、后面是低姿准备 |

## 关键发现

**补抽有效，但峰值选错了。**

1. **补抽确实抓到了 2fps 漏掉的帧**——两处峰值都出现了「模糊帧」，说明快速变化确实被采样到了。
2. **但那不是扣杀，是镜头快速移动/转场。** 帧差分数高，是因为**整个画面都在变**（镜头动了），不是人物在动。
3. 这正好印证霁璃的提醒：**「变化最大不一定是接触时刻，也可能是转场、镜头移动」**。

## 结论

**「补抽」这个机制本身是有效的**（帧数 2 → 11，确实多给了信息），但**「用帧差峰值定位动作」这个前提不成立**——在这个素材上，峰值对应的是转场而不是击球。

要把补抽真正用起来，得换定位方式：
- 姿态变化率（关节移动速度）而不是整像素差
- 或者先排除镜头运动（相位相关/全局位移补偿）再算残差

## 三组小结

| 组 | 结论 |
|---|---|
| 第一组（捏脸） | 网格够用，慢动作能判断 |
| 第二组（羽毛球） | 关键帧没采到，**不是分辨率问题** |
| 第三组（补抽） | 补抽有效，但**帧差峰值不等于动作**，定位方式要换 |

**目前唯一能确定的**：把「关键帧没采到」归因于「网格分辨率不够」是错的。真正的瓶颈在「什么时候该密采」这个决策上。
