# Video Understanding Kit

**把视频整理成 AI 能高效阅读、又能回查证据的结构**：带时间戳的采样帧、镜头分组、六格网格页、贴了字幕条带的增强页与语音转写，外加一层按时间轴把画面和文字串起来的关联表。

不跑 OCR —— 硬字幕由读图的多模态模型直接从放大的字幕条带里读出，落成结构化 JSON 存进阅读库。理由见 [ADR-0019](docs/ADR-0019-remove-ocr.md)。

项目同时提供命令行流水线和 DSH 插件；
插件主要针对手机端开发，不过电脑端也可正常使用。

> **识别结果用于定位候选内容，不是结论。** 关键画面、文字和台词仍应回看原帧核验。
> 性能数字都是单机小样本实测，见下方「实测数据」，可以进行参考，不要直接外推。
> **0.4.0 起不再包含 OCR**：硬字幕由 VLM 读字幕条带得出，模型体积从 ~62 MB 降到 ~31 MB，42 秒视频的处理时间从 132 秒降到 36 秒。

## 解决的是什么问题

让模型"看视频"有三条常见的问题，这个项目分别对应三个设计：

| 问题 | 对应设计 |
|---|---|
| 逐帧喂图，上下文瞬间爆掉 | **网格页**：六帧拼一张，附源帧 ID 与时间戳 |
| 读完字幕就以为看过画面 | **视觉门禁**：`video_report` 核对实际看过的页数，没看够直接拒收 |
| 大量几乎重复的帧浪费额度 | **视觉去重**：帧级 pHash/SSIM → 页级按格覆盖，只留代表页 |
| OCR 在艺术字/气泡/UI 上读错字，错字被当成事实 | **不跑 OCR**：放大的字幕条带交给读图的模型，比逐像素识别更准 |

## 工作流程

![Video Understanding Kit 工作流程](workflow.svg)

```text
视频 → 抽帧 → 帧清单（只读，一份）
        ├─ 视觉：帧差 → 分组 → 分页 → 帧级去重 → 页级去重
        └─ 字幕条带：图像差分定位字幕带 → 切条 → 去重 → 贴到网格页底部
音轨 → ASR → 带时间戳的台词

以上 → 增强页（网格 + 字幕条带）+ pages.json（五要素）
    → VLM 读图 → 字幕文本 + 结论 → 视频阅读库（最近 3 条）
```

## 方法与技术

### 1. 采样与镜头边界

- **基础帧**：按页面预算与时长反推（`--base-fps` 可强制固定 1–12 fps）。这是"呈现帧"，决定网格里能看到什么。默认自动——页数不随时长膨胀。
- **帧差候选**：相邻帧直方图差异超过阈值（默认 8）的时间点标为变化点，用于导航。
- **镜头边界**：**TransNetV2**（ONNX，48×27 输入，窗口 100 帧、步长 100）检测真实镜头切换。窗口**不重叠**——实测切换检测结果不变，耗时减半。
- **补帧**：候选区间内按需二次取帧，补细节。

**镜头边界和帧差只用于时间导航，不代表语义场景或动作结论。**

### 2. 网格页

每页固定 **6 帧**（2×3），每格记录 `cell` 坐标、`t` 时间戳、`srcFrameId` 源帧 ID。组级另有 3×N 导航拼图。

**为什么要网格**：一页图的信息密度远高于单帧，模型能一次看到"一段时间内的连续变化"；同时保留源帧 ID，需要细节时可以精确回取原帧。

### 3. 视觉去重（`lib/dedup.mjs`）

三级判据，从粗到细：

1. **整页 pHash**（阈值 6）：全图 DCT 感知哈希，差异超阈值即判"不同"。
2. **2×3 局部复核**（阈值 10）：整图接近但某一块变化明显时，归入 `visualGroup`（同段，不删）。
3. **按格位覆盖**（0.3.0 新增）：把每页的每个格位单独算 pHash，**当前页的每一格都能在代表页找到同格位且差异 ≤ 6**，才判定被覆盖并删除。

**第 3 级解决的具体问题**：网格页是格子的拼贴，整页哈希会把**排版差异**也算进相似度——6 格页和 3 格页（组末尾不足 6 帧）的格内内容完全一样，整页 pHash 却能差 17–27，导致**每组末尾页永远无法去重**。按格比才问得对问题：*这一页的每一格，代表页里有没有一样的？*

**代表页链而非相邻页**：比较对象是"上一个被判定保留的页"，被删的页不更新锚点。否则 A≈B、B≈C 会推出 A≈C，缓慢变化（镜头推近、表情渐变）会被整段吞掉。

**视觉输入**（[ADR-0015](docs/ADR-0015-ocr-visual-decoupling.md)）：去重**不读 OCR 结果**。曾经有"画面相同但字幕不同就保留"的判据，结果是 OCR 开关静默改变了去重结论（同一视频，OCR 开删 2 页、关删 7 页）。字幕变化属于**内容组织**，在关联层表达，不回头改视觉分组。

### 4. 字幕条带（`lib/band-probe.mjs` + `lib/band-strip.mjs`）

**没有 OCR**。硬字幕的处理分两步：先定位字幕在哪，再把它切成条贴到网格页底部，交给读图的模型。

**定位（`band-probe.mjs`）**：抽 16 帧 → 逐像素方差图 → 行投影 → 找「下半屏里相对邻居孤立地高」的窄带。

判据是字幕的两个固有特征：**位置固定** + **内容高频变化**。画面里的其他东西要么不动（背景），要么整片一起动（镜头运动、人物走动）——后者会被「相对邻居孤立」这个条件排掉。

向上兜底扩展到画面底部 28%：中英多行字幕时，方差最高的往往只是最下面一行（它换得最勤），上面还有一两行。

**切条（`band-strip.mjs`）**：按页的时间范围以 2fps 裁出字幕带 → pHash（≤10）+ SSIM（≥0.88）去重，同一句字幕的相邻帧合并成一段 → 按 **6 格/行**排版（超过换行，不设总上限）→ 贴到网格页底部拼成 `enh-<page>.jpg`。

**为什么要这一步**：帧级去重会把帧删稀（条漫类实测删掉 87.9%），网格里只剩几个时间点，中间的字幕就丢了。字幕条带把这些状态补回来，而且和画面在**同一张图**里——省一次附件，也让「图的哪块对应哪一帧」在同一个坐标系。

**软字幕轨仍然优先**：ffprobe 发现文字字幕轨（`subrip/ass/ssa/mov_text/webvtt/text`）就直接抽 SRT，那条路 0.2 秒，比任何识别都快，也不需要模型。

### 5. 语音 ASR（`asr.mjs`）

- **sherpa-onnx（WASM）** + 中文 Paraformer int8，本地运行，不上传音频。
- 按 **25 秒**切分再识别（`ASR_MAX_SEG`）：Paraformer 整段一次性解码，喂太长会明显跑偏。

**字幕和台词是两条独立结果**：`subsCount` 为 0 不代表视频没声音，ASR 也不能代替画面核验。

### 6. 关联层（0.3.0 新增）

`index.json` 的 `relation` 字段，四张表按时间轴关联：

```text
frames         frameId、timestamp、page、group、cell
visualGroups   groupId、representativeFrameId、memberFrameIds
pages          pageId、groupId、memberFrameIds、时间段 from/to
textEvents     eventId、start、end、text、sourceFrameIds、pages（软字幕轨或模型读出的字幕）
```

三条约束：

1. **去重只减少代表图，不抹掉被合并帧的时间记录** —— `memberFrameIds` 保留全部成员。
2. **同一视觉组可能在不同时间反复出现**，不能拿"最早到最晚"当连续覆盖区间。
3. **一条文字可关联多页，一页可挂多条文字**，也允许文字暂时没有页面承载。

**关联层只生成关系，不回写视觉判定。**

### 6.5 结构化输出与视频阅读库

**每页一份 JSON**（`pages.json`），五要素：

1. 网格图的时间段与 ID：`grid.id` / `grid.from` / `grid.to`
2. 每一帧的时间戳与 ID：`frames[].id` / `frames[].t`
3. 每条字幕的时间戳与 ID：`bands[].id` / `bands[].t` / `bands[].endT`
4. 网格中帧的数量：`frameCount`
5. 字幕条带中字幕条的数量：`bandCount`

另加大条/行/格三层定位（一条大条最多 6 格，超过换行）：

```json
"bandStrip": { "id": "g01-p01-band", "rowCount": 2, "itemCount": 7,
  "rows": [{ "id": "g01-p01-band-r01", "index": 1, "itemCount": 6 },
           { "id": "g01-p01-band-r02", "index": 2, "itemCount": 1 }] },
"bands": [{ "id": "b01", "rowId": "g01-p01-band-r01", "row": 1, "col": 1,
            "t": 0.82, "endT": 1.32, "frames": 2 }]
```

**为什么要行列而不仅是一维序号**：18 格的大条里「第 7 格」不明确，「第 2 行第 1 格」唯一。

**阅读库**（`lib/library.mjs`）：模型读完一页，把字幕文本 + 时间戳提交进来，落成可检索的 JSON。

```text
$DSH_HOME/storages/dsh-video-kit/library/
├── index.json        # LRU 顺序
└── <taskId>/
    ├── video.mp4     # 原视频副本
    ├── reading.json  # 字幕文本 + 时间戳（可全文检索）
    └── meta.json     # 每页 summary / visual
```

**最多保留 3 条**，超出按 LRU 整目录删除（含视频副本）。3 条是手机存储与"最近看过什么"的折中——长期归档应该导出到别处，不该让工具自己无限吃盘。

### 7. 并发与温控

- **CPU 拓扑**：Android 上 `os.cpus()` 返回空数组，只能从 `/sys` 读 `cpu_capacity`。例如这台机器是 1+3+4 三档，**按大核数定并发**，不按总核数。
- **并发上限**：手机 4 路 / 桌面 12 路（抽帧与拼页的 IO 并发，OCR 删除后不再有推理池）。
- **温度分档降档**：`<38℃` 不限 / `38–40℃` 3 路 / `40–42℃` 2 路 / `≥42℃` 1 路。温度可读时以温度为准，不再回落到频率判断——「频率低」既可能是降频也可能是空闲，区分不了。
- **TransNet 走独立 worker**：镜头检测不阻塞主线程的抽帧与拼页。

**实测结论**：同为 2 路，起跑 30.3℃ 用 44.7s，35.1℃ 用 84.1s（慢 88%）；而 2 路改 4 路只快 15.5%。**温度是主导变量，35℃ 以上该降档，只靠加并发效果并不好，而且会导致手机过热。**

### 8. 视觉门禁

`video_report` 拒绝"只看一两页就下全片结论"：

- 覆盖率按**代表性页**算，被去重删掉的页**既不进分子也不进分母**（`droppedExcluded` 单列）；
- 默认要求 30%，逐页全看模式下要求 100%；
- 提示词里的页数要求**直接由门禁算术派生**，不另算一套——曾经出现过「提示说全看、验收按 30%」的分裂。

## 能力清单

- **镜头时间线**：TransNetV2 边界 + 帧差变化点 + 内容分组
- **网格与回查**：六格网格页、组级导航图、源帧 ID、时间戳
- **视觉去重**：三级判据，输出 `kept` / `visualGroup` / `dropped` 三态与代表页映射
- **字幕条带**：图像差分定位字幕带、pHash+SSIM 去重、6 格/行贴到网格页底部
- **语音 ASR**：本地 sherpa-onnx，带时间戳
- **结构化输出**：每页五要素 JSON（网格/帧/字幕条的时间戳与 ID）
- **视频阅读库**：最近 3 条视频的原片 + 可检索的字幕文本
- **关联层**：画面与文字按时间轴关联，互不覆盖
- **补充取帧**：按时间点重新提取原帧，支持裁剪缩放
- **DSH 插件**：五个工具 + 侧栏面板（ASR 开关、逐页全看）

## 安装模型

```bash
pnpm install
pnpm run models     # 视觉模型约 47 MB，不随仓库分发
```

ASR 另需 sherpa-onnx 运行时和中文 Paraformer int8（约 217 MB），见 [asr.mjs](asr.mjs)。

## 命令行使用

```bash
node pipeline.mjs --video video.mp4 --out out              # 只要分组和网格
node pipeline.mjs --video video.mp4 --out out --subs       # 只抽内嵌软字幕轨（不跑 OCR）
node pipeline.mjs --video video.mp4 --out out --asr        # 加语音识别
node pipeline.mjs --video video.mp4 --out out --serial     # TransNet 强制串行（排查用）

node serve-preview.mjs out                                 # 本地预览 http://127.0.0.1:3329
```

| 参数 | 默认 | 作用 |
|---|---:|---|
| `--video` | 必填 | 输入视频路径 |
| `--out` | `out` | 输出目录（非空时需 `--force`） |
| `--subs` | 关 | 提取内嵌软字幕轨（硬字幕由字幕条带 + VLM 读图处理，无开关） |
| `--asr` | 关 | 语音识别 |
| `--base-fps` | 5 | 基础采样率 |
| `--diff-threshold` | 8 | 帧差候选阈值 |
| `--serial` | 关 | 禁用 TransNet worker 并行 |
| `--force` | 关 | 清空并覆盖输出目录 |

## DSH 插件

插件在 [dsh-plugin/](dsh-plugin/)，注册三个工具：

- **`video_analyze`** — 分析视频，返回时间线、分组、网格路径、台词、去重统计、各阶段耗时；同时把视频登记进阅读库
- **`video_look`** — 看第 N 页，**返回增强图（网格 + 字幕条带）+ 该页结构化 JSON**；`dropped` 页默认拦下
- **`video_read_page`** — 把从图里读到的字幕（内容 + 时间戳）落成字符串存进阅读库
- **`video_library`** — 查看阅读库最近 3 条（含完整字幕文本）
- **`video_frame`** — 按时间点取原始帧，支持裁剪缩放

**ASR 开关只能从侧栏面板设置**，工具不接受这个参数——避免 agent 传参把面板开关架空。

侧栏「视频理解」面板：语音识别开关、逐页全看模式。OCR 与基础抽帧率已删除（采样由页面预算自动决定）。

Bilibili 链接（含 `b23.tv` 短链）支持，**暂不支持任意 HTTP 直链**。下载的视频保留 **24 小时、最多 3 条**（新的顶掉旧的）——同一视频重复分析不必重新下载，也避开 B 站限流。

安装步骤、配置项和数据目录见 [插件说明](dsh-plugin/README.md)。

## 输出结构

```text
out/
├── index.json   # 时间线、分组、去重、关联层、耗时
├── base/        # 基础采样帧
├── extra/       # 补充帧
├── grids/       # 网格页与组级导航图
├── band-*.jpg   # 每页的字幕条带
├── enh-*.jpg    # 增强页 = 网格 + 字幕条带（video_look 返回这张）
├── subs/        # 软字幕轨抽取产物
└── audio/       # ASR 音频
```

`index.json` 主要字段：

| 字段 | 内容 |
|---|---|
| `groups[].pages[].frames[]` | 每格的 `cell` / `t` / `srcFrameId` / `extractionId` |
| `dedup` | `stats` + `kept` / `grouped` / `dropped`（含代表页映射） |
| `relation` | 关联层四张表 |
| `subsStatus` | 软字幕轨状态：`disabled` / `completed` |
| `timings` | 各阶段耗时 |

另有 **`pages.json`**：每页的五要素结构与字幕条带行列信息（见「结构化输出」一节）。

## 实测数据

**设备**：vivo V2405A（Android 16，1+3+4 八核）。**素材**：57.4s / 720×1280 / 47 页。**都是单机小样本，不要外推。**

| 对照 | 结果 |
|---|---|
| 4 路 vs 2 路（同基准 253/255ms） | 42.9s vs 50.8s，**4 路快 15.5%**，并行效率 3.07 vs 2.31 |
| 温度影响（同为 2 路） | 30.3℃ 44.7s vs 35.1℃ 84.1s，**慢 88%** |
| 按格去重（表白视频 16 页） | dropped 8 → 9，`g01-p04` 被正确识别为重复 |
| **删除 OCR 前后（大和号 42s）** | **132s → 36s（-73%）**，字幕改由字幕条带 + VLM 读图 |
| 帧级去重（条漫 192s） | 198 → 24 帧（**87.9%**），4 页覆盖 24 页漫画 |

实验记录：[并发 A/B](docs/EXPERIMENT-2026-11-10-concurrency-ab.md) · [重叠对照](docs/EXPERIMENT-2026-11-10-overlap.md) · 全部 [ADR 与实验索引](docs/README.md)。

## 边界：不保证什么

- **低帧率采样会错过**很短的动作、镜头或字幕——5 fps 只是折中。
- **帧差峰值可能来自转场或镜头运动**，不能直接当成动作发生时刻。
- **网格适合浏览和定位**，快速动作可能因为关键帧没采到而无法判断。
- **去重的准确率取决于内容形态**：静态画面重复多，去重效果好；连续微表情变化时 pHash 感知不到，可能误删——这类要靠关联层和回看补。
- **模型读字幕会看错形近字**（`孩子们` → `核子`、`来抓我呀` → `来圳我`），专名、数字、关键语句请回看原帧。这是不跑 OCR 换来的代价：字形判断依赖模型，不依赖专门的识别器。
- **ASR 仍会漏字、错字**，台词同样要回看音频。
- **字幕带定位是启发式的**：假设字幕位置固定且靠下。字幕在画面中间（如条漫气泡）时探测不到，那种内容本来也没有固定字幕带。

## 开发与同步

根目录的 `pipeline.mjs`、`asr.mjs`、`lib/` 是**真源**；插件内副本由脚本生成，不要直接改副本。

```bash
pnpm run sync        # 更新插件内的处理代码副本
pnpm run check       # 打包清单体检 + 副本一致性校验
```

`check` 做两件事：

1. **打包清单体检**（`scripts/check-pack-files.mjs`）：`dsh-plugin/package.json` 的 `files` 白名单 vs 仓库里真实存在的文件，双向比对。漏掉被静态 import 的模块，装上去就 `ERR_MODULE_NOT_FOUND`——这类问题已经出过两次，所以做成检查而不是靠记性。
2. **副本一致性**：`dsh-plugin/lib/videokit/` 与真源逐字节一致。
